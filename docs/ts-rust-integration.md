# Integrating real type checking

## The gap this closes

`src/sandbox.ts` compiles with **sucrase**, which strips types without checking them. Against the
live prototype, this passes and renders:

```ts
interface User { name: string; age: number }
const u: User = { name: "ada", age: "forty" };  // TS2322
const missing = u.emai;                         // TS2339 -> undefined
```

```
ok: true   compileError: None   output: <p>rendered anyway: ada</p>
```

Syntax errors and runtime throws are caught. Type errors are not. For a playground where you read
your own code that is survivable. For an agent writing twenty apps unsupervised it is the missing
safety net — the failure is silent, lands three layers down, and surfaces as `undefined`.

## What replaces it

[`pingdotgg/ts-rust`](https://github.com/pingdotgg/ts-rust) — a Rust port of Microsoft's native
TypeScript compiler, published 2026-10-07, MIT. Not a reimplementation: a port of the real one, so
diagnostics match `tsc`. It has a `wasm32-wasip1` build (`crates/ts_wasm`) with an in-memory
filesystem ABI, which `spikes/wasi-host/` proves runs inside a Worker.

Do not replace the QuickJS execution path. `tsc` emits JavaScript, so it gates it:

```
             ┌─ src/sandbox.ts ──────────────┐
source ──▶   │ sucrase        → JS text       │
             │ QuickJS        → execute        │
             └────────────────────────────────┘
source ──▶   ts_rust.wasm ──▶ diagnostics      ──▶ reject if any
             (type check only, --noEmit)
```

## Shape of the change

### 1. A type-check worker

New `src/typecheck.ts`, modelled on `spikes/wasi-host/tsrust.mjs`:

```ts
import mod from "./ts_rust.wasm";   // 4.2 MB, bundled
import { instantiate, MemoryFs } from "./spikes/wasi-host/wasi-shim.mjs";

export async function typecheck(source: string, filename = "/app/index.ts"): Promise<Diagnostic[]>
```

It writes `source` into a `MemoryFs` alongside a generated `tsconfig.json`, runs `tsc -p /app
--noEmit` with `FLAG_DIAGNOSTICS_JSON`, and returns the parsed diagnostics.

Reuse `wasi-shim.mjs` rather than rewriting it — the WASI shim is the whole cost of running wasm
here, and it is already tested.

### 2. Gate it in the Durable Object

`src/session.ts` runs before `sandbox.run`:

```ts
async run(code: string) {
  const diagnostics = await typecheck(code);
  if (diagnostics.length) return { ok: false, diagnostics, html: "", logs: [] };
  return this.sandbox.run(code);
}
```

In the Durable Object, not the Worker, for two reasons: a 4.2 MB instantiation must not touch the
1-second Worker startup budget, and the session already holds module state there.

### 3. Surface diagnostics

`RunResult` grows a `diagnostics` field. The UI already renders `compileError` and `error`; add a
third block that lists `code`, `file:line`, and `text` the way tsc formats them. That formatting is
the point — an agent reading tsc-shaped output knows what to fix.

## Ordering

| Step | Depends on | Risk if it fails |
| --- | --- | --- |
| 1. Build `ts_rust.wasm` upstream | ~25 GB disk, `binaryen` | Nothing works; fall back below |
| 2. `GET /` on the tsrust harness | step 1 | Real import list is bigger than 5 |
| 3. `GET /typecheck` returns both errors | step 2 | Filesystem ABI is incomplete |
| 4. Add `src/typecheck.ts` | step 3 | — |
| 5. Gate in `AppSession` | step 4 | — |
| 6. UI block for diagnostics | step 5 | — |
| 7. Measure a cold type-check | step 5 | Too slow to be useful |

Do not start at step 4. Steps 1–3 are the whole experiment and cost one build.

## Costs to accept

**One instance per request.** `crates/ts_wasm/src/lib.rs` is explicit: the port keeps one program per
process, so *"the host makes a new instance for each."* Every type-check pays a fresh 4.2 MB
instantiation. Fine for an agent build loop where a run takes seconds. Not viable on a request
path — if a user types, every keystroke would instantiate the compiler.

**Bundle and cold start.** 1.09 MB today; roughly 5.5 MB with the compiler. Under the 64 MiB
limit, but it must be instantiated lazily inside the Durable Object.

**Early and unattested.** 509 stars, created the day of the stream, and the author writes *"I've
never read a line of this code."* 1.3M lines generated by Opus 5.5. Pin the version and expect
breakage.

**No published artifact.** No npm package, no release asset, `ts_rust.wasm` gitignored upstream.
Vendoring a 4.2 MB binary built from an unpinned commit is a supply-chain decision worth making
deliberately: build once, commit the hash, rebuild on a schedule.

## Fallback if any of it fails

Run the real `typescript` package in the Worker instead. Same role, pure JavaScript, no Rust
toolchain, and **100%** diagnostic parity rather than a port's approximation. Costs bundle size
(~8 MB) and one spike to confirm it runs clean in workerd, since it touches some Node APIs.

That is the better trade if the only goal is catching type errors. `ts_rust.wasm` earns its
complexity only if you later want the emitted artifact in the same process — which is the
interesting direction, because `tsc` gives you real types at build time in a Worker, and
`--preserveTypeAnnotations`-style output would let generated apps validate shapes at request time
from the types the author wrote.

Neither is needed for the prototype to be useful. It is needed before an agent can be trusted to
write apps you did not read.
